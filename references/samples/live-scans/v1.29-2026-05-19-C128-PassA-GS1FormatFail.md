## Design decision: "Ignore format fail"

The GS1 format check (`ApplicationPass = "Fail (Data Format)"`) is a configuration
artifact — the user had the GS1 parser enabled but scanned a non-GS1 barcode. The
ISO 15416:2016 grade (OverallGrade = A) is the operative verification result.

**VTCCP behavior (correct as-is):** `OverallGrade` is read directly from the push XML
and is never degraded by `ApplicationPass`. No code change required for the grade.

**To-do:** Parse `ApplicationStandard` / `ApplicationPass` / `ApplicationPassReason`
into `VerificationRecord` for optional display in VCCS report (informational only).

## ApplicationStandard/Pass — new field pattern

These three fields appear when GS1 parser is on. They will also appear on non-GS1 DM/QR scans
if GS1 parser is enabled. They MUST be checked for all scans going forward:

```xml
<ApplicationStandard>Custom</ApplicationStandard>
<ApplicationPass>Fail (Data Format)</ApplicationPass>
<ApplicationPassReason>Data Format</ApplicationPassReason>
```

**Hypothesis**: on scans with GS1 parser off, these fields are either empty or absent.
**To probe**: run a DM scan with GS1 parser off and check if ApplicationStandard is populated.
