## Key Observations

### 1. `ApplicationStandard=Custom` is set on non-GS1 `]d1` DM
**CONFIRMED**: `ApplicationStandard=Custom` on this USPS `]d1` scan, which is definitively
NOT GS1. This means `ApplicationStandard=Custom` is set whenever the GS1 application
parser is active — regardless of whether the symbol is GS1 or not. It is NOT a GS1
indicator. Struck from GS1-DL-2 as a secondary signal.

### 2. FormalGrade push XML format is ALWAYS 2-token
Push XML: `3.5/A` (this passing Grade A scan).  
Push XML: `0/F` (scan #19, total fail).  
Push XML: `2.3/C` / `2.4/C` (scans #17/#18, Grade C).  
**All 2-token.** The 4-token format (`3.5/08/660/45Q`) is only in the HTML report and
the Wireshark codes.xml HTTP channel. GS1-DL-3 is revised: this is not a fail anomaly;
the C# parser must always parse 2-token push XML FormalGrade.

### 3. ANU mismatch confirmed on rectangular DM
Push=59.5, DMST=0.6%. Same raw-unit problem as pharma DM scans. ANUGrade=A (correct).
Further confirms GS1-2 scope extends to all DM symbology, not just GS1 DM.

### 4. Rectangular DM grade fields not emitted by push XML
12 rectangular-specific grade parameters (ULQZ/URQZ/RUQZ/RLQZ + 4 TR pairs + 4 CT pairs)
are all blank in push XML despite being Grade A in HTML. A new push script probe is needed
to surface these for rectangular DM symbols. See DM-RECT-1 in backlog.

### 5. TQZ/RQZ emit `X` on rectangular DM
The square-DM quiet zone fields `TQZGrade` and `RQZGrade` (top/right quiet zone —
applicable only to square DM L-shaped finder pattern) emit `X` on a rectangular symbol
where they have no meaning. VTCCP must not treat `X` as a grade letter when the field is
inapplicable to the symbology shape.

### 6. Base256 encoding + binary data in DecodedData
The DM ECC200 supports Base256 encoding mode (codeword 231 starts it). USPS postage and
other industrial applications use this to embed binary data. VTCCP must:
- Detect Base256 encoded results (e.g. via ErrorCorrectionType, DecodedData byte inspection,
  or Encodation Analysis table)
- Display DecodedData safely (hex dump or escape non-printable bytes) — raw binary will
  corrupt XML serialization and any string display logic
- NOT try to GS1-parse binary data

### 7. ECC200 table — 12×36 entry
DataCW=22, ECCW=18, TotalCW=40. Confirmed from HTML. Push XML `<DataCodewords>` and
`<ErrorCorrectionBudget>` are both empty (same dead path as square DM). C# table lookup
from `<MatrixSize>12x36</MatrixSize>` (outer dimension).
