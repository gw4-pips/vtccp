## Critical finding: VIBGrade behavior

| Condition | VIBGrade | Notes |
|---|---|---|
| Passing QR, version ≤6 (29×29 = v3) | `-` (dash string) | No VIB needed, firmware returns dash |
| **Failing QR, any version** | **`F`** | Firmware returns F on total failure |

**Conclusion**: VIBGrade='-' is only the no-VIB sentinel when the symbol passes
(or can be measured). On a total verification failure, VIB also grades F.
Parser must handle both '-' and 'F' for VIBGrade; 'F' on a fail scan is correct.

## Cognex grade 8.8 — internal FAIL marker

DMST shows several parameters graded `8.8` on this fail scan (UEC, MOD, RM, ANU, GNU, FPD, DECODE).
This is not a real ISO grade — it appears to be Cognex's internal sentinel for
"measurement failed / not computable" in a way that's distinct from a numeric 0.0 grade.
Push XML emits `X` for all of these, which is the correct pass-through.

The ULP/URP/LLP/HCT/VCT/ALP/VIB/FIB grades show `0.0 (F)` in DMST — these ARE
numeric-grade failures (finder patterns, clock tracks, etc. physically damaged/absent).
Those push as 'F' correctly.

## Implication for push script / parser

- **X grade**: firmware emits X for measurements that couldn't be computed (not the same as F)
  - UECGrade=X, MODGrade=X, RMGrade=X, ANUGrade=X, GNUGrade=X, FPDGrade=X, DecodeGrade=X
  - Parser/writer must preserve 'X' as-is; do not convert to F or empty
- **F grade**: ULP/URP/LLP/HCT/VCT/ALP/VIB/FIB all F — finder patterns physically failed
- **Empty strings**: most numeric fields empty when measurement fails
  - MatrixSize, EncodedCharacters, TotalCodewords all '' in push (vs -1 in DMST)
  - C# parser: when MatrixSize='', DataCodewords/ECBudget table lookup must be skipped
