# ISO/IEC 15424 — Data Carrier Identifiers (including Symbology Identifiers)

**Version**: FCD 15424 (Final Committee Draft, 2008-01-19, with FCD edits)
**Source**: ISO/IEC JTC 1/SC 31/WG 1 working document; pre-publication draft of the
second edition. Content is normative; the published ISO/IEC 15424:2008 may differ in
minor editorial detail but is substantively identical.

**GS1 cross-reference**: GS1 General Specifications §5.1.2 (Figure 5.1.2-2) lists the
subset of identifiers used within the GS1 system. All GS1 identifiers are a strict
subset of this standard. See §8 of this document.

**Maintained by**: AIM Global, Warrendale PA, USA — www.aimglobal.org

---

## 1. Structure

A symbology identifier is a three-character ASCII prefix generated by the reading
equipment (NOT encoded in the barcode). Structure:

    ]cm

| Character | Role | Details |
|---|---|---|
| `]` | Flag character | ASCII 93 (0x5D). Signals that the next two characters are the symbology identifier. |
| `c` | Code character | One of A–Z or a–z (case-sensitive). Identifies the barcode symbology. |
| `m` | Modifier character | One or more characters indicating decode options (check digit handling, FNC1 position, ECI, etc.). |

**Key rule**: If a reader has symbology identifiers enabled, it shall ALWAYS transmit
the identifier at the beginning of each message. The receiving application must know
whether identifiers are enabled; a `]` at the start of a data message is always the
flag character, never barcode payload data.

## 3. Modifier Character Tables

The first modifier character shall be from `{0–9, A–Z, a–z}`. In some symbologies it
represents a hexadecimal sum of active processing options.

Where no options apply, the modifier transmitted is `0`.

### 3.7 EAN/UPC — `]E`

EAN/UPC symbols with add-on supplements should normally be treated as two separate
symbols, each with its own symbology identifier. Combined transmission is also supported.

| Modifier | Option |
|---|---|
| `0` | **Standard data packet** — 13 digits for EAN-13, UPC-A, or UPC-E (no add-on) |
| `1` | Two-digit add-on data only |
| `2` | Five-digit add-on data only |
| `3` | Combined: 13 digits from EAN-13/UPC-A/UPC-E + 2 or 5 digits from add-on (15 or 18 digits total) |
| `4` | **EAN-8** / GTIN-8 data packet (8 digits) |

**Device-confirmed**: `]E0` (EAN-13, scan #8)

GS1 note: `]E3` is the preferred format when transmitting EAN + add-on as a single packet.

### 3.8 RSS (GS1 DataBar) and EAN.UCC Composite — `]e`

| Modifier | Option |
|---|---|
| `0` | **GS1 DataBar** — Standard data packet |
| `1` | **GS1 Composite** — Data packet containing data following an encoded symbol separator character |
| `2` | GS1 Composite — Data following an escape mechanism character (no ECI) |
| `3` | GS1 Composite — Data following an escape mechanism character (ECI supported) |

Notes:
- `]e2` protocol corresponds to PDF417 `]L2`; `]e3` corresponds to `]L1`
- For EAN.UCC Composite, two separate transmissions are required. The EAN/UPC component
  is prefixed per §3.7. Modifier values 1–3 shall NOT be used for RSS symbols alone.
- When GS1-128 emulation is enabled, each non-EAN/UPC packet is prefixed `]C1`

**Device-confirmed**: `]Q1` (QR Code Model 2, scans #2–#5, #10, #11, #13, #15)

**ECI/]Q1 clarification** (confirmed from device and standard): The standard defines
\000003 (Latin-1) as the DEFAULT ECI interpretation. When a QR Code uses only the
default encoding (no explicit ECI override), the firmware correctly emits `]Q1` ("ECI
not implemented" as a non-default override). DMST showing ECI=000003 reflects the
default — it does NOT mean the symbol explicitly carries an ECI escape sequence.
`]Q2` would be emitted if the symbol contained an explicit non-default ECI value.
This resolves the earlier interpretation that `]Q1` modifier=1 "encodes ECI presence"
— more precisely: modifier=1 means "standard QR, default Latin-1 interpretation".

## 4. System Expansion — `]Y`

Code character `Y` is not assigned to a specific symbology; reserved for system
expansion. The first modifier character following `Y` is a digit 1–9 defining the
count of remaining modifier characters in the identifier prefix string.

## 7. Annex B — Symbology Emulation (Summary)

Three forms of emulation are defined:

1. **Inherent symbology-specific emulation**: Certain symbologies share a code
   character by design (e.g., MicroPDF417 uses `L`, same as PDF417).

2. **Inherent GS1 application emulation**: `]C1` signifies GS1-128. GS1 may
   authorise future symbologies to also use `]C1` for GS1 application identifier data.

3. **Optional application-specific emulation**: A decoder may prefix data with the
   symbology identifier of an EMULATED symbology rather than the actual carrier, subject
   to four conditions: (a) application specification explicitly permits it; (b) encoding
   symbology is at least as secure; (c) specification defines which identifier to use;
   (d) symbol must encode valid data for the emulated symbology.
   Example: MicroPDF417 may emit `]Cm` or `]Lm` depending on reader configuration.
