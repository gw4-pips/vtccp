# Formal Transfer of FlexWedge RFID and VeriWedge RFID

**Transfer date:** 03 September 2026  
**Transferring project:** GS1 Digital Link Resolver / RFID FlexWedge source project  
**Receiving project:** VTCCP Command Pilot  
**Owner:** VCCS, LLC

## Transfer declaration

Effective upon delivery of the accompanying transfer package to the VTCCP
project, VTCCP becomes the authoritative project and system of record for:

1. **RFID FlexWedge**, the general-purpose RFID keyboard-wedge product; and
2. **VeriWedge RFID**, the market-specific derivative of RFID FlexWedge intended
   for verification workflows.

This transfer covers future source-code maintenance, product development,
feature decisions, releases, defect correction, documentation, integration,
and derivative work for both products.

After acceptance, the RFID wedge material retained in the transferring project
is historical and reference material only. It must not be assumed to remain
synchronized with VTCCP.

## Product lineage

VeriWedge RFID is a derivative of RFID FlexWedge. The two products may serve
different markets and may intentionally have different user interfaces,
features, defaults, integrations, and implementation languages. They are not
required to remain feature-identical.

VTCCP may reuse, adapt, rewrite, separate, combine, rename, or supersede the
transferred implementation as appropriate for each product.

## Transferred baseline

The package contains the Python reference implementation that was validated on
03 September 2026 using:

- Windows 10
- 64-bit Python 3.11
- AsReader P35U over USB VCP
- AsReader P35U C# SDK DLL 1.3.0 supplied by VCCS
- A live SGTIN-96 RFID tag

The validation confirmed:

- P35U connection through the detected COM port
- EPC inventory
- SGTIN-96 decoding
- GTIN-14 and serial extraction
- RSSI and antenna reporting
- lock-status reporting
- separate TID memory read through `CallBackReadTagData`
- TID display in both the last-read panel and read log

This baseline establishes that the transferred reference implementation worked
before transfer. It does not assert that VTCCP's independently developed
implementation has an identical feature set.

## Receiving-project reconciliation

After import, the VTCCP agent should prepare:

1. A summary of the current VTCCP RFID implementation.
2. A source and architecture comparison against this baseline.
3. A feature comparison identifying equivalent, changed, omitted, and new
   behavior.
4. A statement identifying which VTCCP components are authoritative for
   FlexWedge RFID and VeriWedge RFID.
5. Any recommended migration, preservation, or retirement actions.

The comparison should not force the Python and VTCCP implementations to match.
Differences may be intentional and product-appropriate.

## Third-party components

`AsReaderP3xU.dll` is proprietary third-party software supplied under AsReader's
terms. It is included only as a VCCS-provided operational dependency for the
internal handoff. No ownership of that DLL, the AsReader SDK, firmware, or
related third-party intellectual property is transferred.

The receiving project is responsible for preserving applicable third-party
license terms and controlling redistribution.

## Exclusions

The transfer excludes:

- local Python virtual environments
- caches and generated bytecode
- local COM-port assignments
- user configuration files
- tag logs and debug logs
- generated executable/build directories
- unrelated GS1 resolver application code
- the separate ASR-053W RFID TUB project

## Acceptance

Importing or retaining this package in the VTCCP project constitutes technical
receipt of the baseline. The requested VTCCP summary and comparison will
complete the practical reconciliation of the transferred and existing
implementations.
